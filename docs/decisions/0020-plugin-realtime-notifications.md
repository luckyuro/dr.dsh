# ADR-0020：插件实时通知的本机鉴权与投递范围

- 状态：已接受
- 日期：2026-10-26
- 决策影响：daemon、DSH 插件、PWA、安装管理

## 背景

[ADR-0006](0006-notifications.md) 定义了通知分类和最小化载荷，但插件此前只有发送端，
daemon 的本机报告接收及页面展示尚未接通。需要在不增加中继能力、不暴露任意 DSH API 的前提下完成链路。

## 决策

1. 接收器默认关闭。安装记录包含插件时由管理命令启用；源码运行显式使用 `--plugin-reports`
   或 `DSHD_PLUGIN_REPORTS=1`。只支持 daemon 监督启动的 DSH，attach 明确拒绝。
2. 使用随机回环端口和每个 daemon 进程随机生成的 32 字节令牌。地址与令牌经
   `DRDSH_REPORT_URL` / `DRDSH_REPORT_TOKEN` 传给受管子进程，在 DSH 重启时继续传递。
   不把令牌写入 profile、安装配置、命令行或日志。无凭据时插件停用。
3. `POST /report` 要求 Bearer 鉴权，拒绝 `Origin`，限制体积、字段和事件/严重度组合。
   只接受内容最小化的四种插件事件。插件并发和超时均有界，取消订阅时取消请求。
4. 复用已有加密控制流的 `notification` 消息，仅投递给已通过配对设备鉴权的当前连接。
   房间密钥兼容模式不接收；无连接或队列满时明确拒绝，不缓存、不重试、不补发。
5. 页面内保留有界列表和未读数，切换机器或断连时清空。没有 Web Push、系统通知或离线投递。
   既有 wire 结构与共享向量保持不变。

## 被否决的方案

- 固定端口和长期 profile 令牌：同机多实例会冲突，凭据更容易进入备份或配置展示，且需要额外轮换机制。
- 不鉴权的回环 HTTP：浏览器和本机其他用户均可伪造通知，不能仅凭回环地址信任请求。
- 默认启用离线推送：额外引入浏览器订阅和第三方投递基础设施，超出本次实时通知范围。

## 后果

随机端口避免多 daemon 冲突，也省去固定端口配置；临时令牌避免 profile 保存长期秘密。
代价是不能给外部手动启动的 DSH 注入凭据。拥有同用户进程权限的代码可读取子进程环境，
本机令牌不构成针对这类代码的安全边界。

实时通知采用尽力投递，202 只表示进入发送队列，不是浏览器确认。离线与拥塞会丢失事件，
用户仍在真实 DSH 界面中处理审批、提问和任务结果。
