# ADR-0022：插件管理 daemon 的本机基础接口

- 状态：已接受
- 日期：2026-10-28
- 决策影响：原生 CLI、daemon、本机配置与设备登记
- 后续扩展：[ADR-0023](0023-plugin-local-management.md) 补充插件页面、单包原生程序、本机授权与跨宿主退出的作业；本篇保留前两阶段的原始范围。

## 背景

用户希望只安装一个 DSH 插件，并由插件配置和管理后台 daemon，同时保留完整远程访问、
生命周期控制和现有 CLI。插件在 DSH 退出后不能继续接收远程启动命令，因此仍保留独立
daemon，以及 [ADR-0003](0003-no-fork-integration.md) 的进程外监督和带鉴权代理。

本次交付这一方向的前两阶段：管理基础与在线管理。插件发行、Web 管理界面、首次托管交接、
跨宿主退出的更新作业尚不属于这次交付，不能把本机接口可用称为“一键插件安装已经完成”。

现有实现有三个障碍：daemon 安装器反过来拥有插件包；CLI 只有面向人的输出；设备登记在
daemon 启动时读取，运行期间配对与撤销要重启才能生效。插件若直接拼接 CLI 命令并解析输出，
会把这些问题带入界面，还可能在更新时杀掉发起更新的 DSH 宿主和管理子进程。

## 决策

1. **保留原生执行器，明确资源归属。** 旧安装默认由 daemon 管理附属插件；显式选择外部
   插件归属后，插件由 DSH 包管理器拥有，daemon 安装、更新和卸载不得注册、覆盖或移除它。
   通知报告和本机管理开关独立于包资源列表。旧配置按原来的规则解释，旧 CLI 入口继续保留。
2. **配置只有一个来源。** 原生管理层的 `daemon.json` 仍是配置来源。结构化管理入口通过
   同一校验、组件操作锁和原子写入修改它；返回保存结果与重启要求。prefix 和状态目录迁移
   不能伪装成普通字段更新。插件将来只保存实例引用，不另存中继或启动配置副本。
3. **新增本机协议，不改变远程 wire。** JSON 管理入口和 Unix socket 使用显式版本、请求 ID、
   闭集操作与结构化错误。socket 默认关闭，显式启用后由私有目录、文件权限和对端身份约束
   本机访问；不增加 TCP 监听器，不进入 DSH 的通用 RPC，也不进入中继控制协议。
4. **进程锁与数据事务锁分开。** 每个规范化状态目录只允许一个运行中的 daemon。OS 文件锁
   随进程退出释放，不靠 PID 文件猜测存活。设备事务锁只覆盖读取最新状态、合并变更和落盘，
   不能跨配对的网络等待持锁。不同状态目录仍可独立运行。
5. **设备变更在运行中生效。** 启用本机接口时，配对和设备管理优先交给运行中的 daemon；
   未启用时，旧 CLI 仍可用事务锁更新文件，daemon 检测变更。首次配对退出旧房间密钥兼容会话，
   撤销关闭被撤销设备的现有隧道、代理与通知通道。已经配对的登记文件丢失或损坏时拒绝访问，
   不能回退到只验证房间密钥。新增设备不要求重启 DSH。
6. **管理权限不借用报告权限。** 报告令牌仍只允许最小化事件上报。本机 socket 是同用户
   进程管理接口，不是浏览器权限边界。将来接入 Web 管理页时，仍须另加本机管理授权和隧道
   路径隔离；不能因为 DSH 看到 loopback、有效 cookie 或 `Origin` 就允许任意后台管理。
7. **不伪装后台作业已经存在。** 本阶段保留独立 CLI 的同步管理。可能终止调用宿主的结构化
   操作，在受管 DSH 环境中明确拒绝并要求独立管理入口；未来使用独立 systemd/launchd 作业
   完成跨重启操作。非秘密的受管实例标记只是防误操作提示，不是安全授权凭据。

## 被否决的方案

- **把隧道和生命周期全部迁入插件。** DSH 停止时插件随之消失，不能完整保留远程启动和
  崩溃后的退出恢复能力。
- **解析现有人类输出。** 输出不是版本化接口，错误和配对码容易混入日志；结构化入口应
  直接使用结果类型，已有命令的展示格式继续服务终端用户。
- **在线修改登记后仍要求重启 DSH。** 配对和撤销属于权限变更，不能依赖用户另做一次
  服务重启才能兑现；且多个长时间配对任务不能用旧快照覆盖彼此。
- **只靠持久 PID 文件做锁。** PID 会复用，崩溃会留下文件；操作系统持有的锁更符合进程
  生命周期。安装锁与运行锁也不能混为一把，否则正常管理会被后台永久阻塞。
- **插件卸载回调顺便停止 daemon。** 同一个 dispose 会出现在热重载和正常 DSH 退出中，
  不能据此推断用户要求彻底卸载。后台文件必须独立于插件包目录。

## 后果

已有安装与前台运行仍可使用；新接口为后续插件包和管理页面提供明确边界。Relay 与 PWA 的
安装归属、网络协议、加密算法、共享向量都不改变。daemon 新增本机文件锁依赖，用于安全调用
操作系统文件锁；该依赖不进入 relay crate。

代价是需要维护本机协议版本、安装归属的兼容解释、在线与离线两条设备更新路径，以及权限
变更对活跃连接的取消。Unix socket 只覆盖当前 macOS/Linux/WSL2 使用环境，不代表原生 Windows
服务支持。本机同用户代码仍处于现有信任边界内。

操作字段、启用方式、错误和验证命令见[本机管理接口](../operations/daemon-management.md)。
