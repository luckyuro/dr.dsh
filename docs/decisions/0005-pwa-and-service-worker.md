# ADR-0005：远程客户端 —— 中继提供静态应用壳，Service Worker 负责改写

- 状态：已接受
- 日期：2026-09-11
- 决策影响：`apps/pwa`、`crates/dr-dsh-relay`（静态资源面）、`docs/security.md`

## 背景

远程客户端要从**用户完全没有配置过的设备**（一台新手机）打开，因此它需要一个可访问的入口。同时它最终要显示 DSH 的完整界面，而 DSH 的界面只能在服务它的那个 Host 上完成鉴权（ADR-0003）。

于是在"页面从哪来"和"请求往哪去"之间出现了一个必须显式决定的组合：页面必须来自某个公网可达的源，而请求最终必须落到用户家里的 DSH 上。

## 决策

**中继提供静态应用壳；页面的 Service Worker 把 DSH 路径的请求改写进加密隧道。**

### 页面从哪来

中继提供一个**静态、无用户数据**的 PWA 壳：配对界面、隧道管理、以及被代理的 DSH 界面的容器。它不包含任何会话内容、不含任何用户数据、也不为不同用户生成不同内容——它是同一份字节，这也意味着它可以被缓存、被 CDN 分发、被独立审计与固定哈希。

### 请求往哪去

Service Worker 拦截**同源**请求：命中 DSH 路径的请求被改写为 `/__dr/dsh/<原路径>`（隧道前缀），随后由中继转发密文到对应的 daemon。控制面路径（`/__dr/control/…`）与静态资源不被改写——这条边界由 `apps/pwa/src/routing.ts` 的纯函数决定，并有单元测试，因为改写规则错了会导致"把控制请求当成 DSH 请求"这类难以定位的故障。

请求的方法、头、body、`Origin` 与 `credentials` 都被保留：DSH 的请求自带语义（POST body、`accept: text/event-stream`、同源 `Origin`），daemon 负责在 loopback 上忠实复现，而不是重建。

### 会话引导（bootstrap）

具体的时序（细节见 `docs/architecture.md`）：

1. 客户端完成配对、建立加密隧道。
2. 客户端通过隧道请求 `session_bootstrap`；daemon 用就绪行里的令牌换取 DSH 的授权 cookie，并回答一个短有效期的一次性引导路径。
3. 客户端在同源下访问该引导路径，浏览器因此把 cookie 收进**本页 origin** 的 cookie jar 里；DSH 的 303 与一次性令牌语义被完整保留。
4. 此后的页面请求由 Service Worker 改写进隧道，daemon 以 loopback authority 代理到 DSH。

关键点：**DSH 的鉴权没有被跳过，只是由用户自己机器上的进程执行**；远端浏览器始终不持有 DSH 的进程令牌。

## 被否决的方案

### 每个房间分配一个子域（`<room>.relay.example`）

- 否决理由：需要通配符证书（自托管门槛上升），并且把"用户的标识"放进 DNS 与证书透明度日志里。它解决的唯一问题是 authority 一致性，而该问题已在 daemon 侧解决。

### 让远端页面直连 `https://127.0.0.1:<port>`

- 否决理由：浏览器里的 `127.0.0.1` 是**用户自己那台设备**，不是被远程的电脑。这个方案在概念上就不成立，但对不熟悉浏览器网络模型的人很有诱惑力，因此明确记录在此。

### 通过 `--trusted-host` 让 DSH 接受中继的 authority

- 否决理由：同 ADR-0003。放宽 DSH 的 Host 栅栏去适配客户端的便利，是把安全边界换成实现便利。

### 中转所有流量（中继渲染 DSH 界面）

- 否决理由：那会把中继变成必须理解并重建 DSH 前端的组件，既违反零知识（ADR-0002），也意味着 DSH 每次前端更新都要我们跟进。静态壳 + 字节级隧道是与上游解耦的唯一形态。

## 后果

### 正面

- 新设备只需一个 URL：配对码输入后即可用，无需证书、无需配置。
- 远端浏览器不持有 DSH 凭据；cookie 只存在于它自己的 origin 下，且只能通过隧道使用。
- 应用壳可缓存、可审计、可固定哈希，中继侧没有任何按用户生成的内容。
- DSH 的流式与升级请求天然通过（它们只是被改写的同源请求）。

### 负面与代价

- **中继在客户端的可信计算基（TCB）里。** 中继提供应用壳，因此一个被攻破的中继可以向新设备投递被篡改的客户端代码。这是本设计最诚实的弱点，`docs/security.md` 必须显式列出，并给出三条缓解：客户端包的哈希固定与变更提示、自托管中继（应用壳由用户自己的基础设施提供）、以及社区构建的可复现产物的独立校验。
- Service Worker 是浏览器特性，在部分隐私模式或旧浏览器上不可用；此时应降级为明确的错误提示，而不是静默失败。
- `isLoopback` 相关的 DSH 设置面板在远端会降级（DSH 的既有设计），见 `docs/operations/troubleshooting.md`。

### 需要持续留意

- 若未来提供原生移动 App，它将成为"不把中继放进 TCB"的正式解法；届时 PWA 仍是零安装的默认入口。
