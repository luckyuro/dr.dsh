# ADR-0028：持续响应与大型会话快照

- 状态：已接受
- 日期：2026-11-07

## 背景

真实模型验收发现两条此前空白会话无法暴露的路径：DSH 的 `/plugins/events` 永不结束，
完整缓冲会阻止其首条事件到达；多轮任务的历史快照达到 141182 字节，超过代理单块的 65472 字节限制，
导致刷新后会话反复重连。中继的 64 KiB carrier 上限必须保留。

## 决定

daemon 与 PWA 均按响应头、正文块和结束事件转发 HTTP。页面通过可转移 `ReadableStream` 交给
Worker；只为 HTML 注入收集全文。队列上限 8 MiB，实际上游失败会使读流失败。Worker 正常更换时
对 SSE 返回 EOF，触发浏览器重连；普通响应仍报中断，不能将不完整资源当作成功结果。

大型 DSH → 浏览器 WebSocket 文本以 **PX v2** 的 `WsTextChunk` 分片，单块保持 carrier 上限，
整条文本最大 8 MiB。端点按 id、总长、连续字节偏移校验，完成后严格解码 UTF-8；部分结果不交付 UI。
Rust 规范位于 `dr-dsh-proto`，TypeScript 镜像位于 `packages/protocol`，两端读取相同共享向量。
普通消息保留 PX v1；carrier 版本、控制消息、密文转发和中继依赖不变。

## 取舍与范围

- 不扩大 carrier 帧，保留房间间的交错传输和中继内存限制。
- 大快照要求 daemon 与 PWA 同时支持 PX v2；插件自持隧道的 native 也必须更新。旧端点会明确拒绝，不能伪装成功。
- 本次扩展只覆盖 DSH 输出的文本；输入消息与二进制消息继续受 PX v1 的单块限制。
- 当前协议没有单条 HTTP 取消消息：本地停止消费会丢弃迟到数据，上游直到响应或 carrier 结束才释放。
  这项限制没有因流式转发而被隐藏；HTTP 取消协议留待单独设计。

## 验证

共享成功与拒绝向量固定字节格式；真实加密隧道测试覆盖超过 64 KiB 的 UTF-8 WebSocket 消息与后续短消息；
浏览器检查持续插件事件、Worker 更换和大资源传输。跨机验收以原先失败的真实多轮会话刷新为准，
结果记录在[当日验收](../operations/acceptance-2026-11-07.md)。
