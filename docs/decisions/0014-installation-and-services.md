# ADR-0014：统一安装命令，使用系统服务管理器

- 状态：已接受
- 日期：2026-09-15
- 决策影响：源码安装、daemon 生命周期、PWA 与插件分发、运维文档

## 背景

手工构建、复制二进制、编写 systemd/launchd 定义容易造成 PATH、工作目录、配对状态目录不一致。
旧安装示例还曾把密钥文件路径当成 `--room-key` 的值。用户需要一条安装命令和一致的启动、重启、日志入口。

## 决策

1. 提供无第三方运行依赖的 Node CLI `drdsh` 与仓库入口 `install.sh`。构建依赖沿用工作区锁文件，
   未发布阶段只从指定源码构建，不假设存在二进制下载或 npm 发布物。
2. 常驻进程仍是两个 Rust 二进制。CLI 生成 macOS LaunchAgent / Linux systemd 用户服务，
   由系统负责进程身份、退出恢复与日志。安装默认不启动、不启用自启动；调用方显式选择。
3. prefix 决定安装文件与服务名，配置保存绝对路径和必要环境。服务定义不含密钥。
   新配置在构建完成后应用，更新时恢复原有运行状态，卸载保留配置与设备身份。
4. 中继安装同时安装 PWA；插件通过 DSH 的 web profile 插件 CLI 注册。两者的生命周期操作
   映射到各自宿主，不产生额外常驻进程或中继权限。
5. daemon 增加 `DSHD_DSH` 指定可执行文件；SIGTERM 与 Ctrl-C 共用已有停止流程。
   协议和中继依赖不变。

## 被否决的方案

- 自建后台进程管理器与 PID 文件：需要额外处理 PID 重用、锁、崩溃恢复与自启动，复制系统能力。
- 向中继加入生命周期控制接口：会扩大中继的权限和审计边界，违反 ADR-0002。
- 直接编辑 DSH profile 存储：依赖其内部格式，绕过上游公开安装契约；采用 DSH 自己的插件命令。
- 自动 sudo、自动公开端口、默认开机启动：改变机器权限或暴露面，需要由操作者显式选择。

## 后果

### 正面

一套命令覆盖组件安装和运维，原始二进制继续可独立运行；源码目录的构建失败不会清空已安装的 PWA。

### 负面与代价

CLI 需要 Node，安装需要构建工具。服务支持依赖用户服务会话；Windows 原生服务尚未实现，可用 WSL2。
macOS 状态诊断读取 launchctl 输出，需要持续验证系统升级后的格式。更新服务有短暂中断；磁盘故障时
可能需要重装，不声称事务式升级或自动回滚。插件上报接收端、daemon WSS 支持和发布流水线仍是独立缺口。

实际安装和管理服务，不以生成模板的单元测试代替进程行为验证。
