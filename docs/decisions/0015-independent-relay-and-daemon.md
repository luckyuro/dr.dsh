# ADR-0015：Relay 与 Daemon 的独立安装和管理

- 状态：已接受
- 日期：2026-09-16
- 决策影响：组件入口、安装布局、服务生命周期、文档

## 背景

两个 Rust 二进制已经独立，但 ADR-0014 的统一安装配置同时包含 DSH 与中继设置。
即使只更新 PWA，安装器也会重启同一前缀下的 daemon。服务器用户还需要从混合说明中辨认哪些步骤适用。
用户要求把 relay 与 daemon 拆为两个独立部分。

## 决策

1. 在同一源码仓库提供 `relay/` 与 `daemon/` 两个使用入口，各有安装脚本与中英文 README。
   `drdsh-relayctl` 只管理 relay/PWA，`drdsh-daemonctl` 只管理 daemon/可选插件。
2. 同一 prefix 下，使用独立的 `relay.json` / `daemon.json`、程序目录、日志目录、更新锁与服务身份。
   relay 配置不保存 DSH 设置，不创建 daemon 状态目录；daemon 安装不构建或复制 relay/PWA。
3. 更新仅停止对应宿主；PWA 更新只重启 relay，插件变化只重启 daemon。中继重启仍会中断承载连接，
   进程隔离不意味着网络连接永不中断。
4. 源码中的 CLI 构建与服务管理逻辑继续共享；安装后的每个组件携带自己的 CLI 文件。
   Rust crate、共享协议、向量和中继的依赖边界不变。
5. 旧 `install.sh` / `drdsh` 与其安装记录保持可用，普通单组件更新也只重启相关宿主。
   不静默迁移旧状态或启用新服务；迁移由用户停止旧实例后显式指定原状态目录。

## 被否决的方案

- 仅增加两个文档标题：无法消除共用配置与更新时的跨组件重启。
- 复制两套服务管理实现：平台修复与路径转义容易不同步；共用源码，每个安装保存自己的副本即可。
- 拆为两个 Git 仓库并复制协议：当前只需要独立部署，跨仓库同步会增加协议与向量的一致性成本。
- 自动迁移正在运行的旧实例：可能改动现有配对目录或插件注册；保留旧入口，并提供显式迁移步骤。

## 后果

服务器和 DSH 电脑可以各自安装、升级、卸载；同机安装也能验证一侧配置与 PID 不受另一侧更新影响。
两套服务使用不同安装记录，用户需要使用与其安装方式对应的管理命令。旧实例和新实例若同时使用相同端口
或状态目录会冲突，因此迁移说明要求先停止旧实例。

没有引入新网络接口，也没有解决 daemon WSS、插件通知接收端或产物发布等已有缺口。

## 验证

`scripts/drdsh.test.mjs` 检查跨组件参数拒绝、配置边界和服务身份；`scripts/service-smoke.mjs`
调用两个真实安装入口，验证独立安装、更新、卸载和配对状态保留，检查另一侧 PID 与配置不变。
DSH 与插件注册使用替身；这不替代上游 DSH 集成验收。
