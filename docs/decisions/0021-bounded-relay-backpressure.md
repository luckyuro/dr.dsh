# ADR-0021：中继以有界背压转发完整密文帧

- 状态：已接受
- 日期：2026-10-26
- 决策影响：relay、部署容量与故障诊断

## 背景

DSH 0.2.1-rc.2 的一个插件组合资源为 9,198,843 字节。跨机加载时，中继每连接 64 帧的
队列被填满，旧实现的 `try_send` 丢弃当前帧，再向同一个满队列提交关闭消息，后者也失败。
浏览器实测收到 counter 227、预期 215，随后按加密会话规则关闭。这里不能只重置某条 stream：
当前传输使用整个会话的有序计数器，且尚未接入协议库的窗口模型。

## 决策

1. 保留每连接 64 帧的有界发送队列。锁内验证发送者并取得目标连接的发送句柄，锁外等待
   队列容量；不持有全局房间锁等待网络，不为每帧创建后台任务。
2. 队列满时将背压传回读取侧，保留当前帧。不能丢帧后继续同一加密会话，也不增加队列容量。
3. 连接关闭信号独立于数据队列。释放、替换或断开连接时，即使数据队列已满，也能取消
   正在等待的读写；单次排队或写入连续 30 秒没有进展时结束连接并说明原因。
   取消只作用于故障所属的连接注册，旧目标失败不能关闭它的替代者。正常 daemon 离开
   不抢占客户端已经入队的响应，短命配对进程发送的回执仍可排空。
4. 帧格式、加密语义与共享向量保持不变。中继仍只解释帧头，不增加密码学、控制面或 DSH 依赖，
   不持久化或记录 payload。

## 被否决的方案

- 增大队列：只能推迟大文件或慢网络触发故障的时机，同时扩大每连接的内存上限。
- 丢弃当前帧再继续：破坏加密会话顺序，后续看似成功入队的帧也无法使用。
- 固定延时节流：无法适应不同带宽，既不能保证不丢帧，又会降低快速连接的吞吐。
- 以加长浏览器超时掩盖丢帧：等待更久也不会恢复已经丢失的密文。

## 后果

大资源和慢客户端能依赖有界队列与 TCP 背压按序传输；其他房间仍可访问房间表，关闭操作
不再依赖满队列剩余容量。代价是同一发送者的帧扇出可能被慢目标拖延；持续无进展会结束连接，
需要用户重新连接。该措施不提供端点消息优先级，也不等于已经实现协议窗口流控。
