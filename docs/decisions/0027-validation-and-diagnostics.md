# ADR-0027：共享输入校验与结构化诊断

- 状态：采纳
- 日期：2026-11-06
- 接续：[ADR-0023](0023-plugin-local-management.md) 的本机权限边界

## 背景

管理页把配置错误留到提交后报告，PWA 独立判断连接码格式，原生诊断只输出文本。
界面难以定位错误，也没有可供不同前端框架复用的校验接口。

## 决策

1. `packages/validation` 提供无运行时依赖的纯函数与 Standard Schema V1 对象。
   同一份普通 ESM JavaScript 由 TypeScript `checkJs` 检查并生成声明；Node 直接运行，
   浏览器直接加载，不需要框架、DOM 或 Node 专用 API。它实际用于插件服务端、管理页和 PWA。
2. 输入结果为 `{value}` 或 `{issues}`，问题包含字段路径、稳定错误码和中英文提示。
   错误不复制用户输入。配置收集全部错误；端口只接受十进制整数，URL 只接受 WS/WSS origin；
   路径按当前管理宿主 macOS/Linux 的绝对路径校验。配置表单允许空的可选路径和清除 CA。
3. 格式校验不授予权限。DSH 登录、本机来源检查、capability、服务端操作闭集、原生配置校验、
   加密握手和设备授权继续独立执行。配对字母表和密钥格式沿用现有协议，不修改共享向量。
4. `doctor --json` 输出本机报告 `version: 1`，每项包含 `id/title/level/message/remedy`，
   总体状态由最严重检查项决定。默认 CLI 文本和退出码保持兼容；诊断读取审计状态时也不创建目录。
   本机管理继续使用原有 `{text,truncated,exitCode}` 外层，`text` 携带 JSON 报告，失败仍为失败。
5. 管理页将授权、配置、设备、诊断和维护分开。诊断展示逐项状态、建议、筛选和原始输出；
   旧版具名文本行可以回退显示，未知格式和截断输出不能宣称检查通过。
   锁定或授权失效会清除秘密与诊断、取消请求，并丢弃迟到的响应。
6. 插件打包把共享 ESM 收入原生插件包，PWA 构建将其收为扁平模块并原子预缓存。
   Release、源码安装和旧安装入口复用插件 staging，不能依赖部署机器的 workspace 链接。

## 被否决的方案

- 为重新设计界面而整体迁移到 React/Vue：现有两端无需这些运行时，框架接入通过标准接口完成。
- 把前端校验当作权限检查：浏览器输入可绕过，无法替代本机 authority 和 daemon 拒绝规则。
- 只从 CLI 任意文本推断诊断状态：文本变化和执行失败可能被错误显示为通过。
- 为其他 AI Harness 自动发现、启动任意可执行程序：这会改变产品和信任边界，不属于表单框架兼容。

## 代价与边界

- 共享模块需要同时被两种打包路径携带，包导入和离线缓存完整性测试必须覆盖它。
- Standard Schema 定义校验接口，不规定表单事件、响应式状态或提交时转换。
  各框架适配的实际验证范围见[接入指南](../development/validation.md)。
- 浏览器预检仅检测 API 是否存在；doctor 仅检查本机基础环境，均不保证中继、TLS、模型或完整任务可用。
- 本次不改变 wire 协议、中继职责、受支持的 DSH 版本或管理服务的操作系统范围。
